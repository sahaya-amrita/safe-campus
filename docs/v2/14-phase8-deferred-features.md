# 14. Phase 8: floor routing, background sync, phone notices and floating Tom

Built on branch `feat/phase8-deferred` (from `develop-v2` at `78c0172`). This phase covers the four "deferred features" in the roadmap that need code rather than owner action.

## What changed

| Area                         | Behaviour                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Floor-level routing**      | Route-graph nodes may carry a `floor` (ground = 0, basements negative). Edges may be `PATH`, `STAIRS`, `RAMP` or `LIFT`; an edge between floors must be one of the last three. Stairs add a fixed effort per floor (15 m of level walking), so A\* still matches Dijkstra (tested on 100 random multi-floor graphs). **Lifts are stored but never used** for evacuation routes. Step-free routes also leave out stairs, and when nothing remains the app says so and points to Help now; it never invents a refuge. `GET /maps/route` takes `fromFloor` and returns the floor of each point plus `floorChanges`. Routes end at a ground-level node next to the safe point. The map panel asks "Which floor are you on?" and lists plain steps ("Take the stairs down from floor 3 to the ground floor.", "Do not use lifts."). |
| **Background sync**          | When a check-in or SOS is queued while offline, the page asks the browser for a background sync. When the connection returns, the service worker (`public/sw-extra.js`) asks an open app window to send the queue. With no window open, and only if notifications are already allowed, it shows a reminder to open the app. The sign-in token stays in the tab, so the worker never sends anything itself and never says anything was delivered.                                                                                                                                                                                                                                                                                                                                                                               |
| **Phone notices (Web Push)** | Responders can turn on notices for matched help requests on each device (Help requests page → Phone notices). **Off unless** the server has `PUSH_PROVIDER=webpush` and VAPID keys (`pnpm --filter @sahaya/api push:keys`). A notice says only "help request matched to you" (with "DEMO:" in DEMO mode) and opens the inbox: no names, locations or messages. The server sends only to the browser vendors' push services (an allow-list), so a client cannot make it call another address. Success means "accepted by the push service", recorded as `push_devices`; the in-app inbox remains the record. Gone devices are removed automatically. Registering and removing devices is audited (push host only).                                                                                                              |
| **Floating Tom**             | Tom's launcher face is now shaded and three-dimensional. It floats for a few seconds when the app opens, then rests, so it never competes with SOS. It tilts towards the pointer or keyboard focus. With reduced motion, nothing moves. It is still a small inline SVG with no WebGL; Tom's behaviour is unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

Migration `010` adds `push_subscriptions` and the `push_devices` / `push_attempted_at` columns on `help_request_notifications`. The new API dependency is `web-push@3.6.7`.

## Owner actions

- **Phone notices:** generate VAPID keys with `push:keys`. Set `PUSH_PROVIDER=webpush`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` and `VAPID_SUBJECT` as secrets on the API service. Then test on one Android phone and one iPhone; on iPhone, the app must be added to the Home Screen first.
- **Indoor data:** survey buildings floor by floor, marking stairs, ramps and lifts. If the institution designates evacuation lifts, that needs a decision and a model change: today every lift is excluded.
